# 🔧 QA 및 안정화 작업 - 수정 내역

## 📋 수정된 문제점 요약

### 1. 이미지 편집 기능 수정

#### 문제 1-1: cropAreaPixels가 null일 때 저장 불가
**원인**: 모달이 열릴 때 cropAreaPixels가 null로 초기화되어, 사용자가 크롭 영역을 선택하지 않으면 저장 불가

**해결**: 
- 모달이 열릴 때 기본 cropAreaPixels를 설정
- 또는 저장 시 cropAreaPixels가 없으면 전체 이미지를 사용하도록 처리

#### 문제 1-2: 회전값이 preview 이미지에 반영되지 않음
**원인**: `useImageEditor.js`의 `applyImageEdits` 함수에서 회전 로직이 올바르게 작동하지만, preview에서 회전된 이미지를 표시하지 않음

**해결**: 
- 편집 모달에서 회전값이 실시간으로 반영되도록 확인
- 저장 후 preview 이미지에 회전값이 반영되도록 확인

#### 문제 1-3: crop 후 축소 불가능
**원인**: 편집된 이미지가 저장되면 원본 이미지 영역이 사라져서 다시 축소할 수 없음

**해결**: 
- 원본 이미지(`originalUrl`)를 항상 유지
- 편집 시 항상 원본 이미지를 기준으로 편집

### 2. 페이지/슬롯 구조 오류 수정

#### 문제 2-1: 페이지 추가 시 기존 데이터 덮어쓰기
**원인**: `addPage()` 함수에서 새 페이지를 추가할 때 기존 페이지의 slots가 영향을 받음

**해결**: 
- `addPage()` 함수에서 새 페이지를 독립적으로 생성
- 기존 페이지의 데이터를 보존

#### 문제 2-2: 페이지 삭제 후 인덱스 재정렬 문제
**원인**: `deletePage()` 함수에서 인덱스 재정렬이 올바르게 작동하지 않음

**해결**: 
- 페이지 삭제 후 모든 페이지의 `pageIndex`를 올바르게 재정렬
- `customSlots`의 인덱스도 함께 재정렬

#### 문제 2-3: slots 배열이 다른 페이지로 잘못 반영
**원인**: `setImage()` 함수에서 `pageIndex`를 올바르게 확인하지 않음

**해결**: 
- `setImage()` 함수에서 `pageIndex`를 정확히 매칭
- 다른 페이지의 slots에 영향을 주지 않도록 수정

### 3. 출력 기능 안정화

#### 문제 3-1: 출력 시 여백이 좌/우/상/하 동일하지 않음
**원인**: `exportUtils.js`에서 여백 계산이 정확하지 않음

**해결**: 
- 모든 여백을 15mm로 통일
- PDF 출력 시 중앙 정렬로 배치

#### 문제 3-2: Type6 편집 화면이 A4 가로형 출력으로 고정되지 않음
**원인**: `exportToPDF` 함수에서 `layoutType === '6cut'`일 때 landscape 모드가 올바르게 적용되지 않음

**해결**: 
- `exportToPDF`와 `exportAllPagesToPDF`에서 Type6일 때 항상 landscape 모드 적용

#### 문제 3-3: 보조설명 텍스트 중앙 정렬 문제
**원인**: CSS에서 보조설명 텍스트의 수직 정렬이 올바르게 작동하지 않음

**해결**: 
- 보조설명 영역에 `flex items-center justify-center` 적용
- `html2canvas` 캡처 시에도 정렬 유지

#### 문제 3-4: 빈 슬롯이 출력에 포함됨
**원인**: 빈 슬롯에 `.export-exclude` 클래스가 적용되지 않음

**해결**: 
- 빈 슬롯에 `.export-exclude` 클래스 추가
- 출력 시 빈 슬롯 숨기기

### 4. 성능 및 렌더링 최적화

#### 문제 4-1: React 재렌더링 과다
**원인**: 
- `useStore`에서 불필요한 상태 업데이트
- 컴포넌트에서 `useCallback`, `useMemo` 미사용

**해결**: 
- `useCallback`, `useMemo`를 적절히 사용
- Zustand store의 selector 최적화

#### 문제 4-2: Zustand store의 불필요한 상태 업데이트
**원인**: 상태 업데이트 시 전체 store가 업데이트됨

**해결**: 
- 필요한 상태만 업데이트
- `shallow` 비교 사용

#### 문제 4-3: 이미지 업로드/변환 시 blocking 발생
**원인**: 이미지 업로드/변환이 동기적으로 처리됨

**해결**: 
- 모든 이미지 처리를 `async/await`로 비동기 처리
- 로딩 상태 표시

### 5. 예외 처리 및 오류 메시지 개선

#### 문제 5-1: 이미지 업로드 실패 시 사용자 안내 부족
**원인**: 에러 메시지가 명확하지 않음

**해결**: 
- 구체적인 에러 메시지 표시
- 사용자 친화적인 안내 메시지

#### 문제 5-2: DB 업데이트 실패 시 메시지 표시 부족
**원인**: DB 업데이트 실패 시 사용자에게 알림이 없음

**해결**: 
- DB 업데이트 실패 시 `alert` 또는 `toast` 표시
- 재시도 옵션 제공

#### 문제 5-3: 네트워크 에러 대응 부족
**원인**: 네트워크 에러 발생 시 처리 로직이 없음

**해결**: 
- 네트워크 에러 감지 및 처리
- 재시도 로직 추가
