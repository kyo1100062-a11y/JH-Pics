# 🧪 프로덕션 환경 테스트 시나리오

## 📋 테스트 목적

프로덕션 환경에서 실제 사용자 관점에서 전체 플로우를 테스트하여 배포가 정상적으로 완료되었는지 확인합니다.

---

## 🔐 시나리오 1: 로그인 및 인증

### 테스트 목적
사용자 인증이 정상적으로 작동하는지 확인

### 테스트 절차
1. 배포된 사이트 접속 (예: `https://your-project.vercel.app`)
2. `/login` 페이지로 이동
3. 유효한 이메일과 비밀번호로 로그인 시도
4. 로그인 성공 후 홈으로 리다이렉트 확인
5. Header에 사용자 이메일과 "로그아웃" 버튼 표시 확인

### 예상 결과
- ✅ 로그인 성공
- ✅ 홈으로 자동 리다이렉트
- ✅ Header에 사용자 정보 표시
- ✅ "로그아웃" 버튼 클릭 시 로그아웃 및 `/login`으로 리다이렉트

### 체크 포인트
- [ ] 로그인 폼이 정상적으로 표시됨
- [ ] 로그인 성공 시 에러 없음
- [ ] 인증 토큰이 올바르게 저장됨
- [ ] 로그아웃 시 세션이 정상적으로 종료됨

### 실패 시 확인 사항
- Supabase Auth 설정 확인
- 환경 변수 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 확인
- 브라우저 콘솔 에러 확인
- 네트워크 탭에서 API 호출 확인

---

## 📁 시나리오 2: 프로젝트 CRUD

### 테스트 목적
프로젝트 생성, 수정, 삭제가 정상적으로 작동하는지 확인

### 테스트 절차
1. `/projects` 페이지로 이동
2. "사업 추가" 버튼 클릭
3. 프로젝트 이름 입력 후 저장
4. 생성된 프로젝트 목록에 표시 확인
5. 프로젝트 이름 수정
6. 프로젝트 삭제 (Admin 권한 필요)

### 예상 결과
- ✅ 프로젝트 생성 성공
- ✅ 프로젝트 목록에 즉시 반영
- ✅ 프로젝트 수정 성공
- ✅ 프로젝트 삭제 성공 (Admin만 가능)

### 체크 포인트
- [ ] 프로젝트 목록이 정상적으로 로드됨
- [ ] 프로젝트 생성 시 DB에 저장됨
- [ ] 프로젝트 수정 시 DB가 업데이트됨
- [ ] 프로젝트 삭제 시 DB에서 제거됨
- [ ] 일반 사용자는 삭제 버튼이 비활성화됨

### 실패 시 확인 사항
- Edge Function `projects` 배포 확인
- Edge Function 로그 확인: `supabase functions logs projects --tail`
- 네트워크 탭에서 API 호출 확인
- 인증 토큰 확인

## 📸 시나리오 3: Picture Set 생성 및 편집

### 테스트 목적
Picture Set 생성, 편집, 저장이 정상적으로 작동하는지 확인

### 테스트 절차
1. `/upload` 페이지로 이동
2. 템플릿 선택 (예: 4컷)
3. 메타데이터 입력:
   - 제목: "테스트 사진"
   - 사업명: 드롭다운에서 선택
   - 보조사업자: "홍길동"
   - 담당자: "김철수"
4. "저장" 버튼 클릭
5. URL이 `/edit/:id`로 변경되는지 확인
6. Picture Set이 DB에 저장되었는지 확인

### 예상 결과
- ✅ Picture Set 생성 성공
- ✅ URL이 `/edit/:id`로 변경됨
- ✅ DB에 저장됨
- ✅ 메타데이터가 올바르게 저장됨

### 체크 포인트
- [ ] 템플릿 선택이 정상 작동함
- [ ] 메타데이터 입력이 정상 작동함
- [ ] 저장 시 로딩 상태 표시됨
- [ ] 저장 후 URL 변경됨
- [ ] DB에 데이터가 올바르게 저장됨

### 실패 시 확인 사항
- Edge Function `picture_sets` 배포 확인
- Edge Function 로그 확인
- 네트워크 탭에서 API 호출 확인
- 필수 필드 검증 확인

---

## 🖼️ 시나리오 4: 이미지 업로드

### 테스트 목적
이미지 업로드, Storage 저장, 미리보기가 정상적으로 작동하는지 확인

### 테스트 절차
1. Picture Set 편집 화면에서
2. 이미지 슬롯 클릭
3. 이미지 파일 선택 (JPG, PNG, HEIC 등)
4. 업로드 진행 확인
5. 이미지 미리보기 표시 확인
6. Storage에 파일이 업로드되었는지 확인
7. 이미지 URL이 Storage URL로 변경되었는지 확인

### 예상 결과
- ✅ 이미지 업로드 성공
- ✅ 이미지 미리보기 표시
- ✅ Storage에 파일 저장됨
- ✅ 이미지 URL이 Storage URL로 변경됨
- ✅ HEIC 파일이 자동으로 JPG로 변환됨

### 체크 포인트
- [ ] 이미지 선택이 정상 작동함
- [ ] 업로드 진행 상태 표시됨
- [ ] 이미지 미리보기가 정상 표시됨
- [ ] Storage에 파일이 저장됨
- [ ] 이미지 URL이 올바르게 변경됨
- [ ] HEIC 파일 변환이 정상 작동함

### 실패 시 확인 사항
- Edge Function `upload` 배포 확인
- Storage Bucket `pictures` 존재 확인
- Storage RLS 정책 확인
- 파일 크기 제한 확인
- Edge Function의 Service Role Key 확인

## 📄 시나리오 5: PDF/JPEG 출력

### 테스트 목적
PDF/JPEG 출력이 정상적으로 작동하는지 확인

### 테스트 절차
1. 이미지가 업로드된 Picture Set 편집 화면에서
2. "PDF 출력" 버튼 클릭
3. PDF 파일 다운로드 확인
4. PDF 내용 확인:
   - 메타데이터가 올바르게 표시됨
   - 이미지가 올바르게 표시됨
   - 여백이 올바르게 적용됨
5. "JPEG 출력" 버튼 클릭
6. JPEG 파일 다운로드 확인

### 예상 결과
- ✅ PDF 파일 다운로드 성공
- ✅ PDF 내용이 올바름
- ✅ JPEG 파일 다운로드 성공
- ✅ JPEG 내용이 올바름

### 체크 포인트
- [ ] PDF 출력 버튼이 정상 작동함
- [ ] PDF 파일이 다운로드됨
- [ ] PDF 내용이 올바름
- [ ] JPEG 출력 버튼이 정상 작동함
- [ ] JPEG 파일이 다운로드됨
- [ ] JPEG 내용이 올바름

### 실패 시 확인 사항
- `html2canvas` 설정 확인
- Canvas 요소 선택 확인
- 브라우저 콘솔 에러 확인
- CORS 문제 확인 (외부 리소스 로드 시)

## 🔄 시나리오 6: 전체 플로우 통합 테스트

### 테스트 목적
실제 사용자 시나리오를 따라 전체 플로우가 정상적으로 작동하는지 확인

### 테스트 절차
1. **로그인**
   - 배포된 사이트 접속
   - 로그인

2. **프로젝트 생성**
   - `/projects`로 이동
   - 새 프로젝트 생성

3. **Picture Set 생성**
   - `/upload`로 이동
   - 템플릿 선택
   - 메타데이터 입력
   - 저장

4. **이미지 업로드**
   - 여러 이미지 업로드
   - 이미지 편집 (크롭, 회전, 확대/축소)
   - 보조설명 추가

5. **페이지 추가**
   - 페이지 추가
   - 새 페이지에 이미지 업로드

6. **PDF 출력**
   - 전체 페이지 PDF 출력
   - 내용 확인

7. **저장 및 재접속**
   - 저장
   - 페이지 새로고침
   - 데이터가 유지되는지 확인

### 예상 결과
- ✅ 모든 단계가 정상적으로 완료됨
- ✅ 데이터가 올바르게 저장됨
- ✅ 재접속 시 데이터가 유지됨

### 체크 포인트
- [ ] 로그인 → 프로젝트 생성 → Picture Set 생성 → 이미지 업로드 → PDF 출력 전체 플로우가 정상 작동함
- [ ] 데이터가 DB에 올바르게 저장됨
- [ ] 재접속 시 데이터가 유지됨
- [ ] 에러 없이 모든 기능이 작동함

### 실패 시 확인 사항
- 각 단계별 에러 메시지 확인
- 브라우저 콘솔 에러 확인
- 네트워크 탭에서 API 호출 확인
- Edge Functions 로그 확인
